# AI_WORKFLOW

How FindMyJam is built with AI. A living log, updated as the work progresses.

## 1. Tools and models

| Tool | Used for | Why |
| --- | --- | --- |

## 2. Harness

Generated by the `project-setup` plugin, then adapted to the project.

### 2.1 Context and rules

| File | Role |
| --- | --- |
| `CLAUDE.md` | Loaded in every session: sources of truth, architecture and code rules, test rules, commands. |
| `SPEC.md` | Spec-Driven Development target: scope, model, rules `Rn`, failure matrix, acceptance criteria `ACn`, API. |
| `docs/implementation-contract.md` | Public API and names shared by tests and code, so black-box tests compile against code they never see. |

### 2.2 Settings (`.claude/settings.json`)

| Setting | Value |
| --- | --- |
| `permissions.allow` | `Bash(git status:*)`, `Bash(git diff:*)`, `Bash(git log:*)`, `Bash(npm run:*)`, `Bash(npm test:*)`, `Bash(npx jest:*)`, `Bash(npx tsc:*)`, `Bash(maestro test:*)` |
| `permissions.deny` | `Read(./.env)`, `Read(./.env.*)`, `Read(**/.env)`, `Read(**/.env.*)` |
| `hooks` | PostToolUse → typecheck-ts.sh; PreToolUse → guard-bash.sh |
| `enabledPlugins` | expo@claude-plugins-official, code-review@claude-plugins-official, ponytail@ponytail, superpowers@claude-plugins-official |

`.claude/` and `CLAUDE.md` are gitignored: the harness is local to this machine.

### 2.3 Skills

| Skill | Role |
| --- | --- |
| `commit` | Conventional Commits with project scopes; reads the real diff; `SPEC.md` committed alone first; asks before `git commit`. |
| `ui-design` | Checks every UI change against `DESIGN.md` and the theme tokens, accessibility and states; `check-design.sh` is the static check. |
| `tdd` | Test-first loop (red → green → `npm test`, `npx tsc --noEmit`, `npm run lint`), unit / component / Maestro per layer, mocking rules, tests named after `ACn` / `Rn`. |

### 2.4 Hooks

| Hook | Event and scope | Role |
| --- | --- | --- |
| `guard-bash.sh` | `PreToolUse` on `Bash` | Blocks any command touching `.env` (`.env.example` allowed) and any force push. |
| `block-main-source.sh` | `PreToolUse`, declared in `test-designer` only | Enforces the black-box rule: no reads in `src/` or `supabase/` except `__tests__/`, `src/test-utils/` and `.maestro/`, which are also the only writable paths (`.claude/hooks/black-box.conf`). |
| `typecheck-ts.sh` | `PostToolUse` on `Write\|Edit` | `tsc --noEmit` of the project after an edited `.ts` / `.tsx` file; type errors go back to Claude. |

### 2.5 Subagents

| Subagent | When | Role |
| --- | --- | --- |
| `spec-reviewer` | After a task, before committing | Read-only review of the diff against `SPEC.md` and `CLAUDE.md`; coverage tables for ACs, failure scenarios and rules; verdict `OK` / `CHANGES NEEDED`. |
| `test-designer` | Before implementing an AC | Writes failing tests from `SPEC.md` only (`tdd` skill preloaded); `block-main-source.sh` blocks the implementation and git history, and allows writes to test paths only. |

Intended loop for a feature: `test-designer` (red) → implementation with the `tdd` skill (green) →
`spec-reviewer` → `commit` skill.

## 4. Where the AI got it wrong, and how it was noticed

| # | What | How it was noticed | Fix |
| --- | --- | --- | --- |
| 1 | A `jest.mock` factory referenced `Text` from outside its scope | The test suite failed to run (babel-jest hoisting error) | `jest.requireActual('react-native')` inside the factory |
| 2 | A "break the code, see the test go red" check copied a backup to a scratchpad folder that did not exist | `cp` failed and the `&&` chain stopped before the break | Created the folder, reran the check (2 tests went red, file restored) |
| 3 | A ChatScreen test failed once in a full run | It passed alone and on the rerun | Not fixed; listed in `DECISIONS.md` §4 |
| 4 | Three files mixed the end-date and calendar features, so they could not be committed separately with `git add` | Reading the diff before committing | Staged only the end-date parts, then type-checked and tested that snapshot on its own |
| 5 | The `--scopes` passed to the setup script had commas inside descriptions, which split the scopes | Reading the generated commit skill | Rewrote the scope list by hand |
| 6 | The existing `commit` skill had been copied from another project (scopes `auth`/`front`/`mcp`, a "time-tracking app") | Reading it during the setup | Replaced with the FindMyJam version |
| 7 | Text added to `CLAUDE.md` split the sentence pointing to the `tdd` skill | Reviewing the file after the edit | Moved the sentence back |
| 8 | The new migration row in `DATABASE.md` landed between the waitlist migration and its deployment note | Rereading `DATABASE.md` for this file | Moved the row after the note |
| 9 | Testing the env-file guard hook with an `echo` containing the file name was blocked by that same hook | The hook refused the command | Ran the hook cases from a script file |
